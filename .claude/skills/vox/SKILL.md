# Харнесс озвучки vox

Полные правила — `AGENTS.md` в корне харнесса. Здесь — порядок работы и запреты.

## Порядок

1. Узнайте проект: `python -X utf8 vox.py --book <папка> next` (или инструмент MCP `vox_next`).
   Команда называет ближайший шаг и готовую строку запуска — выполняйте её, а не держите конвейер в голове.
2. Книга: ingest → draft → attribute (пакеты; несколько агентов — `attribute claim --worker <имя>`) →
   cast → pron → check → approve → **pilot** (одна глава) → freeze → plan → synth → qc → review → assemble →
   qc splices → master.
3. Короткие тексты: проект `init --kind clips`, сценарий `clips/<имя>.md` (docs/SCRIPT_GUIDE.md), `clips plan`,
   затем `clips render --yes` с разрешения.
4. После синтеза — `qc run`, затем `review` (HTML-страница: пользователь слушает и жмёт принять/отклонить),
   решения применяются `qc apply <файл>`.

## Нельзя

- Платное (`synth`, `clips render`, `say`, `pilot run`, `cast design/audition`, `pron trial`, `attribute run`,
  `qc run` с gemini) — только после явного «да» пользователя на показанный план и цену. MCP такие команды не выполняет.
- Читать или копировать файлы с ключами (`*Cred*`, `.env`) и выводить ключ.
- Менять слова книги: разрешены CAPS-акцент, ё, пунктуация и теги из таблицы Google.
- Повторять оборванный запрос без `ledger resolve`; удалять файлы кэша, журнала, релизов.

## Справочники

- `docs/GEMINI_TTS.md` — модели, голоса, style, теги, цены, ошибки API.
- `docs/SCRIPT_GUIDE.md` — как писать сценарий и подачу.
- `docs/MONTAGE.md`, `docs/QC_ASR.md` — монтаж, громкость, проверка.
- `docs/ASSESSMENT.md` — где агенту можно доверять, а где нужен слух человека.
